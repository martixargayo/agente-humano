# WHY (2026-ready robustness upgrades)

## WorldState: evidencia + confianza
El WorldState ahora conserva evidencia estructurada (`evidence_items`) y meta de trazabilidad, y los flags se derivan con umbral de confianza. Esto reduce falsos positivos como “no negocio” sin contexto y permite separar deadline/urgency con días estimados. La evidencia se deduplica por ventana temporal para evitar ruido repetido. Impacto: mejor señalización de fase/precedence/intent sin cambiar consumers existentes.

## Intent: utilidad + progreso + decay
La intención ya no depende de un score rígido. Usa utilidad (beneficio vs coste), progreso real y decaimiento de confianza para evitar intenciones “pegadas”. El sistema abandona cuando no hay progreso, manteniendo compatibilidad (slots/steps intactos) y reduciendo loops. Esto mejora realismo sin tocar el orden de nodos.

## Guardrails: enforcement real
Las restricciones ya no son solo texto en el prompt. El planner filtra por inputs requeridos y reglas duras (ej. respeto de BATNA). El executor pasa la respuesta por un validador que corrige violaciones críticas (números propios y sobrepasar límite) con una reparación LLM controlada. Se mantiene un solo intento de reparación para evitar loops.

## Policies enriquecidas
Cada policy tiene contrato explícito (required_inputs, target_slots, expected_effects, failure_modes). El planner recibe estos campos para elegir con mayor precisión y el executor los usa para guiar la respuesta. Esto mejora la selección del LLM con menos ambigüedad.

## Tradeoffs
Más campos y validaciones añaden complejidad y tests, pero aportan verificabilidad y estabilidad. Se mantiene retrocompatibilidad: flags antiguos siguen existiendo y el grafo no cambia.
